01 — 基本概念

这个平台在干什么

一句话：拿同一批历史客户，重新跑一遍不同的审批策略，看谁批得更好。

信贷审批策略就是一套「批不批、批多少」的规则加模型。换策略是有风险的动作——批松了坏账上来， 批紧了生意做不成。回测就是在不动真钱的前提下，先在历史数据上比一比。

角色含义
Champion 冠军当前线上跑着的策略，基线。默认 v2.2
Challenger 挑战者想替换冠军的候选。默认 v2.3
Beta更早期、通常更激进的试验版本。默认 v2.4-Beta

四套内置策略，场景都是「黑五大促提额」：

版本通过率坏账率 MOB12RAROC特点
v2.2 冠军22.7%1.53%19.7%保守基线，稳定运行 18 个月
v2.3 挑战者43.5%1.76%23.9%重训模型，通过率接近翻倍而坏账几乎没动
v2.4-Beta65.8%3.72%20.5%激进，18–25 岁客群有公平性问题
v2.5-RC48.8%2.38%22.6%图网络反欺诈
这张表本身就是一个问题 v2.3 通过率从 23% 提到 44%，坏账只涨了 0.2 个点。这是真的吗？多批的人从哪来？可持续吗？ 第 3 节的 Swap-set 把答案摊开，第 4 节的增量分解告诉你这个增量该走哪条审批路径。
02 — 上手

五分钟跑通第一次实验

cd ~/Documents/Qoder/credit-backtest-studio
bash scripts/ctl.sh start

一条命令拉起前后端（后台运行，等后端健康检查通过才起前端）。浏览器打开 http://localhost:5173。

命令干什么
ctl.sh start / stop / restart起 / 停 / 重启。改了 .env 或依赖后用 restart
ctl.sh status谁在跑、健康不健康、AI 通没通
ctl.sh logs api跟踪日志（api | web）
ctl.sh doctor体检：依赖、端口、健康、是否在跑假数据
ctl.sh test跑后端 + 前端测试

  1. 配置页

    左边选 Champion / Challenger / Beta 和样本；右边两张卡片是样本信息和仿真环境。 先保持默认「历史回放」，第 5 节再换。顶部还有自然语言输入框（需要 DeepSeek key）。

  2. 点「运行回测」

    几秒钟，8 万行数据跑完 L1–L5 全部指标。

  3. 结果页

    顶部信息条给出样本、样本量、run_id、snapshot_sha； 下面是仿真环境卡片和可信度卡片，然后是切片筛选器和 L1–L5 五个标签页。

  4. 切一刀试试

    切片筛选器选「年龄段 = 18-25」，页面重算。注意顶部——run_id 变了。 这是刻意设计，第 11 节解释。
如果页面顶部出现橙色的「演示数据」横幅 说明前端没连上后端，你看到的所有数字都是假的。跑 ctl.sh doctor 看是哪一环断了。 这个横幅是故意做得很显眼的——在信贷工具里，编造的数字和实测的数字长得一模一样是不可接受的。
03 — 读结果

看懂 L1–L5 五层指标

五层不是五个报表，是五个逐步收紧的问题。前一层过不了，后一层的数字没有意义。

L1 模型质量：模型分得清好人坏人吗

指标大白话怎么算好
KS好人和坏人的分数分布拉开了多远0.3 以上可用，0.4 以上不错
AUC随机取一好一坏，模型把坏人排前面的概率0.5 = 瞎猜；0.7 可用；0.75+ 好
Brier预测概率准不准，不只是排序对不对越小越好
排序单调性分数从低到高，坏账率是不是真的一档比一档高出现反转 = 那一段分数没有意义
PSI这个月的客群比基期漂移了多少<0.1 稳定 / 0.1–0.25 观察 / >0.25 报警
CSI具体是哪个特征在漂同上

实测：v2.2 KS 0.309 / AUC 0.702；v2.3 KS 0.338 / AUC 0.720。

常见误读 AUC 高 ≠ 能赚钱。模型只负责排序，赚不赚钱取决于你在哪里切一刀（cutoff）——那是 L2 的事。

L2 商业价值：这套策略赚不赚钱

指标大白话
通过率100 个申请批了几个
坏账率批出去的人里最后坏了几个
户均利润每批一户平均挣多少
RAROC挣的钱扣掉预期损失，再除以占用的资本

页面上除了比率还有规模化数字：核准户数、总敞口、总利润、预期损失、经济资本。 比率回答「划不划算」，规模回答「值多少钱」——v2.3 比 v2.2 多批 16,651 户，这个数才是要签字的东西。

为什么看 RAROC 不看利润总额：多批一定多挣绝对额，但那可能是拿更多资本和更多风险换来的。 RAROC 把收益、风险、资本放在同一个分母上比较。

常见误读 通过率必须和坏账率一起看。单说「v2.4-Beta 通过率 65.8%」很漂亮，配上「坏账 3.72%，是冠军的 2.4 倍」就不一定了。

L3 风险：放出去的钱坏得多快

  • Vintage 曲线：同一批客户放款后第 1…12 个月的累计坏账。曲线越晚翘头越好。
  • Roll rate 迁徙率：M1→M2→M3+ 的恶化比例，看逾期客户是自己好转还是继续烂下去。
  • FPD 首期违约：这个高通常不是风险问题，是欺诈或进件质量问题。

这一层现在是实测的：合成账簿带时间轴（放款月份、首次逾期 MOB、逾期阶段）， 三个指标都从账户级明细数出来，不是坏账率的函数。 上传的数据集若没有时间列，页面会标注「派生」——那种情况下这一层只是 MOB12 的换算，别当独立证据用。

常见误读 坏账率是「截止今天」的快照。新放的款还没到暴露期，天然好看。Vintage 存在的意义就是消除这个错觉。

L4 Swap-set：整个回测的灵魂

两套策略批的人大部分是重叠的。真正的差异只在两个格子里：

谜题的答案 v2.3 多批进来的 19,456 人坏账只有 2.34%，而它拒掉的 2,805 人坏账高达 4.28%。 通过率翻倍而坏账基本持平，是因为它一边多批了一批相对干净的人，一边把冠军批错的高风险客户挡住了。

还有两个数要看：一致率（两套策略决策相同的比例，太高说明挑战者没新意，太低说明它在乱来）和 p 值（swap 两侧的坏账差异有多大可能只是运气，p > 0.05 就不能说「更优」）。

页面上还有一张归因表：每一笔 swap 是被哪条规则改判的（评分闸门 / DTI 闸门 / MOB 闸门 / 定价）， 以及每条规则各自的坏账。这张表是下一节「增量来源分解」的原料。

L5 公平性：会不会歧视某类人

指标大白话红线
DI ratio某群体通过率 ÷ 参照群体通过率< 0.8 触线 四分之五规则
TPR gap不同群体「该批的批到了」的比例差越小越好
特征重要性模型主要靠什么判断出现受保护属性 = 严重问题
策略female / maleoutsider / local18-25 vs 26-55
v2.2 冠军0.9840.9920.796
v2.3 挑战者1.0120.9870.839
v2.4-Beta0.9991.0030.534
注意谁触线了 触线的是现役冠军 v2.2（0.796），挑战者反而把这一项改善到 0.839。 默认这一跑的评审结论是「不可推进」，原因不在挑战者身上，在基线身上——这正是评审包要说清楚的东西。
为什么这层不能跳过 性别并不是模型输入，通过率照样可能出现组间差异——因为负债率、工作年限这些变量本身与人群分布相关。 这叫间接歧视，只能靠 DI 这类指标测出来。
04 — 三张卡片

增量从哪来、能不能信、怎么拿去评审

L1–L5 告诉你数字是多少。这三张卡片回答的是另外三个问题。

4.1 增量来源分解

「同样坏账率下多批一倍」在拆开之前不是结论。多批的人可能是模型变准换来的（旧模型误杀、新模型重新排序）， 也可能是闸门放松换来的（DTI 从 0.65 放到 0.70）。这两条路径走完全不同的审批流程。

卡片直接给出一句话结论，是从归因表算出来的算术，不是叙述：

模型驱动 84% 政策驱动 16%
卡片原文 增量的 84% 来自模型区分度提升（被旧模型评分拦下、被新模型重新排序的客群），只有 16% 来自政策放宽； 换入客群坏账 2.34%，换出客群坏账 4.28%，即多批的比拒掉的更干净。 这条路径按模型升级审批，不按政策放松审批。

如果哪天这个比例翻过来（政策驱动占多数），卡片会变成琥珀色——这就是提醒你换审批路径的信号。

4.2 可信度卡片

这张卡片跑的是和 Agent 的 Critic 完全同一套确定性红线。 给人看的和给模型看的必须是同一套判定，否则「你信页面还是信 Agent」就成了一个真问题。

卡片头部一个标签：无阻断 有提示 · N 被阻断 · N，展开后每条红线一行，带具体数值。三个按钮：

一键复现

同配置换 3 个种子重跑，给均值、标准差、95% 置信区间，以及最关键的一项：排序有没有翻转。

找修复

自动搜索一条能清掉这条红线的阈值路径。每次尝试都是一个真实 run，并回答：清掉了没有、有没有引入新的阻断项。

下载评审包

把上线评审需要的证据打成一个 Markdown 文件，见 4.3。

只对能修的红线给按钮 「找修复」只出现在有旋钮可拧的红线上（DI、坏账上限、核准户数）。 protected_attribute_as_input（受保护属性入模）没有按钮——给它一个按钮，等于承诺一个不存在的修复。

4.3 评审包（Evidence Bundle）

一个 Markdown 文件，装的是策略上线评审需要的全部东西：候选 run 及其 manifest、红线报告、多种子复现结果、 拒绝推断的方法误差、增量归因表、审稿意见，以及——这一包没有回答的问题清单。 

结论：不可推进
理由：存在 2 项阻断级红线，必须先解决

本包没有回答：
· 未做多种子复现：本结论仍基于单次抽样
· 历史回放环境：拒绝客群无表现数据，放开准入后的客群变化未被验证
· 无行为反馈仿真：接受率、用信率随额度变化的影响未被建模
三档结论，没有第四档 只有 不可推进 / 证据不足 / 可提交人工评审。没有「可以上线」这一档—— 上线永远是人的动作，平台最远推进到「可以拿去评审」。

如果你在下载前先点过「一键复现」，包里会带上复现结果，「本包没有回答」里那一条会自动消失。

05 — 可信度

拒绝推断：这个行业最大的结构性盲区

回测有一个致命的结构性问题：你只知道你批过的人后来还没还钱。被拒掉的人，你永远不知道他们本来会怎样。

所以上面那个「挑战者多批的 19,456 人坏账 2.34%」——这个数在真实生产环境里根本测不出来，只能估。 行业标准做法叫拒绝推断（Reject Inference）。

这个平台做了什么不一样的事

合成账簿里所有人都有真实标签，所以直接做拒绝推断毫无意义。平台反过来用：

  1. 先遮蔽

    把冠军拒绝掉的那 6 万多人的表现数据藏起来，还原真实生产条件。

  2. 再估回来

    用选定的推断方法估计这批人的坏账。

  3. 拿真值反算误差

    用被藏起来的标签，算出这个方法错了多少。
第 3 步才是重点 每家机构都在做第 2 步，并把结果当成测量值汇报。几乎没有人报第 3 步。

配置页 → 仿真环境 → 「拒绝推断（L0b）」→ 选方法 → 运行。结果页顶部环境卡片展开后：

方法估计坏账真实坏账偏差相对误差
忽略拒绝客群0.00%2.34%−2.34pp
100%
差额分摊 行业惯用~4.1%2.34%+1.8pp
80% 上下
v2.4-Beta 同法对照5.11%4.67%+0.44pp
9%
这张表在说什么 行业里最常用的差额分摊方法，在这份账簿上把新客群风险高估了将近一倍。 拿这个数去做额度政策决策，你会因为一个方法误差而错过一个本来成立的策略。 同一个方法在 v2.4-Beta 上误差只有 9%——方法的可靠性取决于客群，不是取决于它的名气。

一次比完四种方法（不用跑四次回测）：

curl -s -X POST localhost:8000/api/agent/tools/compare_ri_modes \
  -H 'content-type: application/json' \
  -d '{"args":{"config":{"champion":"v2.2","challenger":"v2.3",
       "sample_id":"consumer_2024q1q2"}}}'

相对误差超过 50% 时，reject_inference_unreliable 直接变成阻断级红线—— 方法误差比它声称的效应还大，这个结果不能用。

环境会主动告诉你它不能回答什么

历史回放 L0a 不能回答 放开准入后新客群的表现 · 长期客群迁移 · 任何依赖客户对政策做出反应的问题
拒绝推断 L0b 不能回答 行为反馈（接受率、用信率随额度变化）· 多期滚动 · 精确到小数点后一位的坏账预测

这不是免责声明，是硬约束：超出环境能力的结论会被第 10 节的红线拦下来。

06 — 探索

调策略旋钮：不换策略，只挪阈值

六个白名单旋钮，其他一律报错——能挪阈值，不能重新定义策略。

target_approval_rate · dti_limit · mob_months · mob_dpd_max · score_cutoff · limit_increase_min/max

一次扫出一条权衡曲线（服务端展开，不用调 N 次）：

curl -s -X POST localhost:8000/api/agent/tools/sensitivity_scan \
  -H 'content-type: application/json' \
  -d '{"args":{"base_config":{"champion":"v2.2","challenger":"v2.3",
       "sample_id":"consumer_2024q1q2"},
       "strategy":"v2.3","knob":"target_approval_rate",
       "values":[0.3,0.4,0.5,0.6]}}'

每个点都是一次独立、可引用、可复现的 run。这条曲线就是通过率与收益的权衡曲线，用来找拐点。

07 — 稳健性

这是结论，还是运气

一次回测只是一次抽样。「v2.3 的 RAROC 比 v2.2 高 4 个点」可能是策略的性质， 也可能只是这一份样本的性质。一次运行永远分不清这两者。

页面上点「一键复现」即可；命令行等价物：

curl -s -X POST localhost:8000/api/agent/tools/replicate_across_seeds \
  -H 'content-type: application/json' \
  -d '{"args":{"config":{"champion":"v2.2","challenger":"v2.3",
       "sample_id":"consumer_2024q1q2"},"n":3}}'

返回每个指标的均值、标准差、95% 置信区间，以及最关键的一项： 排序在不同种子下有没有翻转。

判定规则 排序翻转 = 这个差异来自抽样，不是策略差异。平台会直接把结论判为 not_supported， 置信度封顶 0.25，不给解释余地。
08 — 自动化

让 Agent 自己跑一轮

左侧「Agent 调查」页输入一个问题，看它分阶段实时跑完。命令行：

curl -s -X POST localhost:8000/api/agent/investigate \
  -H 'content-type: application/json' \
  -d '{"goal":"v2.3 放宽通过率后 RAROC 是否还优于 v2.2",
       "base_config":{"champion":"v2.2","challenger":"v2.3",
                      "sample_id":"consumer_2024q1q2"},
       "budget":{"max_experiments":5}}'

返回的 events 里能看到它依次走过的每一步：

阶段干什么
prior_work先查有没有人问过同样的问题，查得到就不重复烧算力
plan把目标翻译成一组可证伪的实验，必须包含基线对照
experiment逐个执行，走和你点按钮完全相同的代码路径
guardrails确定性红线检查，在任何叙述产生之前
findings读紧凑指标表给出发现
replication花剩余预算做多种子复现
critique对抗性审稿：样本量、多重比较、单一种子、公平性、环境边界、过拟合
为什么拆成 Analyst 和 Critic 两个角色 同一个模型既找结论又验证结论，它一定会验证通过。Critic 拿到的红线报告是不可推翻的事实： 只要存在阻断项，verdict 强制降为 not_supported，置信度封顶 0.3。

没配 DeepSeek key 也能跑，三步都有确定性兜底（默认计划＝基线＋通过率扫描）。 配了 key 才有真正的假设生成和归因分析。 预算是在工具层强制的，不是在提示词里劝的——说服不了它。

09 — 历史

实验树与两次对比

因为 run 不可变，一个问题往往会长出好几个 run。流水账是错的形状。

实验日志

流水，最新在上。除了 KS / AUC / RAROC，每一行都带红线判定： 无阻断 有提示 被阻断， 鼠标停上去看具体是哪几条。一个不能上线的 run 不该跟能上线的长得一样——这是这一列存在的全部理由。

实验树

同一个 root_run_id 的 run 收成一条线索，按父链缩进：

● a1b2c3d4-e5f 无阻断 通过率 43.5% · 坏账 1.76% · RAROC 23.9% └ f6g7h8i9-j0k 被阻断·1 切片 age_band=18-25 · 通过率 38.1% └ k1l2m3n4-o5p 无阻断 参数覆写 v2.3.dti_limit=0.62

线索层面直接告诉你：这条线索问的是什么、最后的结论是什么、里面几个被阻断几个干净。 这也是「找修复」点完之后你该来的地方——每次尝试都是树上一个节点，能看到它从哪个 run 派生、拧的哪个旋钮。

两次对比

在日志或树里给任意两行分别按 A 和 B，点「对比这两次」。两个刻意的设计：

按角色对齐，不按版本号

A 的挑战者对 B 的挑战者。按版本号匹配的话，一次角色互换的实验就会让你读出完全相反的结论。

配置差异印在指标差异上面

不知道哪个输入动了（种子？切片？旋钮？），指标差值没有意义。manifest 相同时页面直接说：输入相同，任何差值都是引擎 bug。

通过率那一行永远没有优劣 它只跟坏账率一起看才有方向，页面拒绝替你下这个判断。
10 — 边界

红线表：什么时候不该相信结果

红线由确定性代码算出，模型说服不了它，你也说服不了它。

级别代码触发条件为什么
阻断disparate_impact 任一群体 DI < 0.80四分之五规则，合规红线
阻断approved_book_too_small 核准户数 < 500坏账率没有统计意义
阻断protected_attribute_as_input 上传策略把性别 / 种族等作为模型输入直接违规
阻断reject_inference_unreliable 推断方法相对误差 > 50%方法误差比它声称的效应还大
警告swap_not_significant swap-set p > 0.05差异可能只是运气
警告rank_ordering_broken 分数段坏账出现反转那一段分数没有排序意义
警告replay_only_environment 使用历史回放环境无拒绝客群表现、无行为反馈
警告其他 坏账超上限 · AUC < 0.6 · 样本 < 5000 · 目标通过率 > 90% · 推断误差 25–50% 结论成立，但必须带着这个说
一条容易被忽略的规则 缺失的指标不等于零指标。某个策略没有 L2 数据时，校验会跳过它， 而不是判它「通过率 0% 触线」。
11 — 机制

为什么切片之后 run_id 变了

因为每个 run 都是不可变的证据。

切片、换种子、调旋钮，都会产生一个新的 run，通过 parent_run_id / root_run_id 挂在原来那个下面。原来的 run 一个字都不会被改。 去实验树（第 9 节）看这条线索长什么样。

原因很直接 Agent 会引用 run_id 作为结论的证据。如果昨天引用的 run_id 今天指向了另一份数据，整条证据链就废了。
字段是什么
run_id这次运行的身份
manifest_sha复现哈希：把所有会影响数值的输入——数据内容、策略代码、种子、旋钮、切片、环境、指标版本——折成一个 SHA-256
snapshot_sha旧版短哈希，保留兼容

不变式：相同 manifest_sha ⇒ 相同数值。所以提交实验时平台会顺手告诉你 「这个实验之前跑过，run_id 是 xxx」，直接复用不重算。 

curl -s localhost:8000/api/experiments/<run_id>/manifest   # 你是怎么算出来的
curl -s localhost:8000/api/experiments/<run_id>/lineage    # 这条线索上都有谁
12 — 沙箱

上传自己的策略：沙箱的边界

策略页可以上传 Python 策略（实现 score() 和 approve()）。它跑在一个隔离子进程里。

能用：numpy、pandas、scipy、sklearn 这些计算库，以及正常的 Python 语言特性——class、继承、type / object / super 都可以。

拦住什么怎么拦的
读写任何文件open 从内建里删掉，子进程里连 builtins.open 本身都关了
联网socket 关掉
动态执行代码eval / exec / compile / __import__ 全部移除
绕过隔离的经典手法上传即 AST 扫描，所有 dunder 属性（__class__、__subclasses__、__globals__…）一律拒绝
跑死机器CPU 6 秒、内存 1 GiB、写盘 4 MiB 的硬上限

被拒时报错会告诉你具体是哪一行的哪个东西不允许。

为什么这么严 backend/.env 里放着你的 API key。在加固之前，一段上传的策略可以 open('backend/.env').read()，把 key 编码进它返回的 float 数组带走——这条路现在是堵死的。 这也是「让 AI 写策略代码」那一步的前提：能自动生成代码，就必须假设代码不可信。
13 — 接入

让 Claude Code 直接指挥平台

平台的 16 个工具可以原样暴露成 MCP server：

claude mcp add backtest -- backend/venv/bin/python -m app.mcp.server
需要 Python 3.10+ 当前 backend/venv 是 3.9，要用得另建一个 3.10+ 的 venv。 依赖里已经加了版本标记，所以 3.9 环境下 pip install 不会失败，只是没有这个 server。

接上之后可以直接说人话：「帮我扫一下 v2.3 通过率 0.3 到 0.7，找出 RAROC 拐点，然后对拐点那个配置做三种子复现」。

预算按连接计（40 次实验 / 1 小时），在工具层强制。 错误是分类的（budget_exceeded / invalid_request / not_found）， 不是抛栈——外部 agent 能据此改行为，而不是重试到死。

14 — 路线

三条上手路线

10 分钟 · 先建立直觉

  • 默认配置跑一次
  • L2 看三个版本的通过率和坏账，注意「规模化数字」那一栏
  • L4 看 swap-in / swap-out 两个格子——理解 v2.3 为什么能「又松又稳」
  • 看 L4 下方的增量来源分解：84% 来自模型，不是放松政策
  • 切片到 18–25 岁，回 L5 看 v2.4-Beta 的 DI 掉到 0.534

30 分钟 · 理解可信度

  • 展开可信度卡片，看默认这一跑为什么被阻断（是冠军 v2.2 的 DI=0.796，不是挑战者）
  • 点「一键复现」，看排序稳不稳
  • 对 disparate_impact 点「找修复」，看它搜出来的阈值路径和诊断表
  • 下载评审包，重点读最后那段「本包没有回答什么」
  • 换成拒绝推断环境跑一次，展开误差表；compare_ri_modes 一次比完四种方法

深水区 · 让 Agent 干活

  • 「Agent 调查」页跑一轮，重点读 guardrails 和 critique
  • 故意给一个会踩红线的目标（比如把 v2.4-Beta 当挑战者），看它怎么被拦下来
  • 去实验树看这一轮生出了多少个 run，挑两个做对比

16 — 排障

常见问题

页面顶部有橙色「演示数据」横幅

前端没连上后端，页面上所有数字都是假的。ctl.sh doctor 看哪一环断了， ctl.sh logs api 看后端报什么。

AI 解读面板没反应

没配 key。在 backend/.env 填 DEEPSEEK_API_KEY，然后 ctl.sh restart。 Agent 闭环不配也能跑（走兜底），但 AI 解读和自然语言配置需要。

改了依赖 / .env 之后怎么办

ctl.sh restart。脚本会检查 requirements.txt 的时间戳，变了就自动重装依赖—— 之前「少装一个包导致后端起不来」的坑就是这么堵上的。

端口被占用

API_PORT=8001 WEB_PORT=5174 bash scripts/ctl.sh start

回测跑得慢

第一次要生成 8 万行数据并标定各策略阈值，之后有缓存。同配置重复提交会直接命中 manifest 缓存，秒回。

为什么默认这一跑就「不可推进」

因为现役冠军 v2.2 在 18–25 岁客群上 DI=0.796，压在四分之五规则线下。 这不是挑战者的问题——挑战者反而把它改善到 0.839。评审包会把这个事实摆出来，而不是替你把它藏起来。

这些数据是真的吗

不是。是按信贷业务逻辑生成的合成账簿——评分、负债率、多头借贷、放款月份、逾期表现之间保持真实的相关结构。 所有指标都是真算出来的，不是硬编码。

能用自己的数据吗

可以。数据集页上传 CSV 并做列映射，策略页上传自己的 Python 策略。两个注意： 上传的数据集没有真值列，拒绝推断的误差标定用不了，只能跑历史回放环境；没有时间列的话 L3 会标注「派生」，那一层不能当独立证据。
