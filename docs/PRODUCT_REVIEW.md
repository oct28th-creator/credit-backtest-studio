## 1. 拒绝推断的结果在哪里看

**结果页顶部「仿真环境与可信度」卡片**——前提是配置页选了「拒绝推断（L0b）」环境。展开后是每个策略 swap-in 客群的「估计坏账 / 真实坏账 / 偏差 / 相对误差」。

它**不会**改写 L1–L5 的指标。这是刻意的：L2 的坏账率是"真值"（合成账簿全员有标签），拒绝推断的输出是"如果你在生产环境只能估，你会估成什么样"。两个数放在一起才有意义，混在一起反而没法看。

💭 **一个待决策的产品问题**：要不要在 L2 加一列「生产可得估计」——即把 swap-in 客群的坏账替换成推断值后重算通过率/坏账/RAROC，与真值并排。这会让"方法误差最终影响了哪个决策数字"一眼可见，但也让 L2 的表变宽。我倾向做，作为一个开关。

## 2. 策略对比：从描述两套配置，改成解释结果 ✅

原「策略对比」= AI 拿两套策略定义写一段描述。它回答"两套策略长什么样"，而人要问的是"差异解释了结果里的哪部分"。

本轮做了 **Swap-set 归因**，放在 L4 面板四象限下方：

- 规则差异清单（cutoff 680→650、DTI 0.60→0.68、MOB 12→6 …）
- **换入归因**：挑战者批了、冠军拒了——冠军是凭哪条规则拒的，每条规则的户数、占比、坏账率
- **换出归因**：反过来，挑战者凭哪条规则拒掉了冠军批的人
- 换入/换出客群各自的 **RAROC**（按准入方的定价算）

默认样本实测（v2.3 vs v2.2）：

| 换入原因（冠军的规则） | 户数 | 占比 | 坏账率 |
|---|---|---|---|
| 风险评分不足（旧模型 cutoff） | 16,442 | 84% | 2.32% |
| 近期逾期记录（MOB 12 → 6） | 2,599 | 13% | 1.77% |
| 负债率过高（DTI 0.60 → 0.68） | 503 | 3% | 2.19% |

| 换出原因（挑战者的规则） | 户数 | 占比 | 坏账率 |
|---|---|---|---|
| 风险评分不足（新模型） | 2,785 | 100% | 5.17% |

**读法**：v2.3 的收益 84% 来自模型重训（新模型把旧 cutoff 拦下的人重新排序），只有 16% 来自政策放宽；而它换出的人 100% 是新模型识别出的高风险客户。这是「模型升级」的证据，不是「政策放松」的证据——两者的上线审批路径完全不同。

AI 的对比端点（`/api/ai/compare/stream`）现在拿到的 facts 也包含这张归因表和红线报告，不再只看策略定义。

原独立「策略分析」页保留为静态的规则 diff 视图（评审材料用）。🔜 下一轮可把它降级为 L4 归因卡片的"查看完整定义"链接。

## 3. L1–L5 指标体系审计

### 多余 / 误导（本轮已标注，🔜 建议处理）

| 项 | 问题 | 本轮 | 建议 |
|---|---|---|---|
| **L3 全部** | FPD = 坏账×0.32，迁徙率、Vintage 均为 MOB12 坏账率的确定性函数。**L3 是 L2 的另一种画法，零信息增量。** | ✅ 返回体加 `derived: true`，面板加「由 L2 推导」标签，AI prompt 禁止把它当独立证据 | 🔜 要么给合成账簿生成真实的逐月表现（放款月、逐期还款状态），要么把 L3 折叠进 L2 作为可视化 |
| **L1 PSI/CSI** | 来自模拟月度队列（固定 seed=42、n=5000），与本次 run 的数据、切片、种子**无关** | ✅ 种子改为跟随 run；标 `simulated_cohorts`；面板加标签 | 🔜 同上，需要时间轴 |
| L5 `reason_coverage` | 放在公平性层不合适，它是可解释性/拒绝理由覆盖 | — | 🔜 移到 L2 拒绝原因旁 |

### 缺失（本轮已补 ✅）

| 项 | 为什么重要 |
|---|---|
| **L1 排序能力（rank ordering）** | AUC 高不代表每个分段都单调。cutoff 恰好落在一个倒挂的分段上时，AUC 看不出来。现在按 pd̂ 十分位给坏账率 + `rank_monotonic` 标志 |
| **L4 归因表** | 见第 2 节 |
| **L4 换入/换出 RAROC** | 政策变更真正被评判的是**边际**客群的收益，不是全量。之前只有全量 RAROC |
| **红线报告进 UI** | guardrails 之前只有 Agent 看得到。现在结果页有「可信度」卡片，人和机器看同一份判定 |
| **多种子复现进 UI** | 「可信度」卡片一键跑 3 个种子，看排序会不会翻转 |

### 缺失（🔜 建议下一轮）

| 项 | 为什么重要 |
|---|---|
| **L0 数据质量层** | 样本代表性、缺失率、标签成熟度（是否真到 MOB12）、时间泄漏检查。现在环境层只覆盖了一部分 |
| **L2 规模化数字** | 总增量余额、总 EL、总利润、占用资本。raw 里有 `economic_capital`，前端没展示。决策者最终看的是绝对额 |
| **L2 「生产可得估计」列** | 见第 1 节的待决策项 |
| **L5 多维 DI** | 目前固定三个维度（性别 / 年龄 / 渠道）。应支持按任意切片维度算 DI |
| **L4 分段一致率 → 分段 swap 坏账** | 现在按分数段只有一致率，应加每段的换入/换出坏账 |

| 现有 | 状态 |
|---|---|
| 自然语言 → 实验配置 | 有，只做单次解析 |
| 逐层解读（L1–L5） | 有，现在带红线约束 |
| 问答 | 有 |
| 报告生成 | 有 |
| 策略对比 | 有，现在看得到归因表 |

| 🔜 新增机会 | 价值 |
|---|---|
| **归因表 → 一句话结论** | "v2.3 的收益 84% 来自模型升级而非政策放宽"——这句话是从归因表算出来的，AI 只负责说人话 |

## 5. Agent 不只是解释：按前沿产品的设计

你的理解对了一半——**在 UI 里**，Agent 之前确实只有解释能力，因为闭环只暴露在 API。本轮加了「Agent 调查」页，它现在能做的是：提一个问题 → 自己设计实验 → 真跑 → 过红线 → 做复现 → 对自己挑刺 → 结论写回注册表。每个 run 可点开。

这是起点。下面是 Agent 在这个产品里应该长成的样子，按优先级：

### 5.1 调查（Investigator）✅ 已有，需要打磨
**一句话 → 一份带证据链的答案。** 关键不在于 LLM 有多聪明，在于三个硬约束：预算在工具层强制、红线不可推翻、复现不稳就判 not_supported。这三个约束让它的输出可以被审计。

🔜 打磨点：Designer 用真模型时要限制"一次只动一个变量"；Critic 应主动调用 `compare_ri_modes` 而不是只提建议。

### 5.2 评审包（Evidence Bundle）🔜 最高优先级
**策略上线评审需要的一切，一键打包**：候选 run 及其 manifest、红线报告、多种子复现、RI 方法误差、归因表、审稿意见、以及**没做的实验清单**。

为什么这是最高优先级：它是这个平台跟"回测工具"的真正分界线——回测工具输出数字，评审包输出**可以签字的证据**。而且它几乎不需要新能力，只需要把现有的组装起来。

### 5.3 策略作者（Author）🔜
**从目标生成候选策略，而不只是调现有策略的阈值。**
- 一级：生成 `policy_overrides` 组合（今天已经能做）
- 二级：生成 Python 策略代码 → 沙箱验证 → 回测 → 审稿。这就是你之前想的 Strategy Authoring Copilot
- 前提：沙箱升级。LLM 写的代码不能跑在当前的 demo 级隔离里

### 5.4 监控（Monitor）🔜
**每月新数据到了自动重跑冠军**：PSI 漂移超阈值 → 自动开一个调查会话 → 给出"要不要重新校准"的建议。这是 Risk Operations Agent，需要时间轴数据（第 4 节的根本问题）。

### 5.5 MCP server 🔜
把 `tools.describe()` 包成 MCP server，Claude Code / Cowork 能直接指挥平台做实验。工具层已经是自描述的，工作量小。

### 什么不该让 Agent 做
- **上线**。永远是人的动作。Agent 最远推进到评审包。
- **自定义指标口径**。指标定义冻结在 `METRIC_VERSION`，Agent 不能发明新指标。
- **越过环境边界下结论**。`not_valid_for` 是硬约束。
